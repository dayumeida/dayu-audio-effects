## 已恢复处理链

1. Float32输入转换Double，阈值检测用独立滚动矩阵；|x|≤1e−7的值置零。
2. 振幅直方图（48k为6530格），端部平滑、正负峰搜索、宽度映射、RMS及阈值历史，产生上下削波阈值、容差、邻域长度。Type 1指数1.25/容差750，Type 2指数1.4199999570846558/容差850，Type 2还包含二级峰分支。
3. 候选区域聚合、邻域验证、长度拆分、跨窗口保留与合并。Type 1候选阈值系数1，Type 2为0.8。48k最大区域435帧。
4. 每声道独立修复：小段平均值、Bessel样条预填、双向Burg LPC预测、方向权重融合、幅度保护及区域状态1→2→3→4。标准100阶，高质量150阶；标准复用近邻预测系数，高质量重新估计。
5. 输出增益，随后立体声关联的原装限制器：3ms延迟、峰值/RMS检测、动态释放。保留目标float运算顺序及原生 `__exp10f`。

## 原装内存错误与生产规则

原装LPC函数0x43348中residual分配150 doubles，但后续预测分支0x44558按削波区长度读取。48k长度可达435，96k可达870。正常AU的LLDB观测证实读取了相邻负系数、反向上下文、备份系数，96k还读入另一声道多项式，且malloc跨页间隔变化。

`reference-long-repeatability.json` 保留原装两次独立正常进程的对照：48k Type 2标准同一输入有117138个Float32样本不同，首次74674，最大绝对差1.139731988310814；高质量该输入两次一致。故任何“任意输入、采样率、进程完全逐bit等价”结论均不成立。

生产规则：卷积残差仅前order项有效，其后的预测激励明确为零，作纯AR外推。所有缓存按prepare分配的长度有界访问；不复制相邻对象或跨声道的内存污染。Analysis中可显式启用有限参考heap-tail模型，仅用于解释原装48k捕获，不应生产启用。此项有意修复原装缺陷；不把修复后的Type 2长区域称为原装逐bit一致。

## FCP集成要求

所有工作缓存仅prepare中分配，render中无分配、无锁、无后台线程等待；reset应清除直方图历史、滚动区、修复状态、多项式、限制器和调度未完成任务。mono/stereo和任意宿主块必须输出相同对齐声音。

忠实同步参考实现存在原装相同的突发计算：48k标准Type 1约35ms峰，高质量约100ms峰，超过512帧/48k的10.667ms预算。生产采用额外一个工作步长的固定调度缓冲，将Burg阶迭代、预测样本和区段流程分摊至下一个hop；48k新固定延迟7871帧。最终调度预算与安全测试记录另列，未经验证不得将同步峰值版本标成FCP性能完成。

协商采样率范围16k–384k；8k原装直方图平滑宽度会退化为0，未作为生产支持范围。常用44.1/48/96k优先验收。prepare仅在非实时阶段执行；不通过render动态扩容。

## 最终冻结与验收

最终生产依赖为7个头文件，清单及SHA256见 `final-header-manifest.json` / `final-sha256.txt`。`ERA5DeClipperReferenceCore.hpp`、Profile目录和各探针仅作分析验证，不复制到生产。必须使用 `-ffp-contract=off`，不得启用fast-math；明确NEON FMA仅用于已恢复的vDSP点积归约，其他运算保留目标顺序。

生产core显式调用 `repair_.setReferenceHeapTail(false)`；安全零尾部没有UI开关。额外对NaN/Inf输入置零、有限超范围输入限制到±64，修复矩阵非有限值回退到相应原始输入；稳定旁路直接输出固定延迟后的原始输入，切换使用5ms交叉淡化。质量/类型/De-Clip/增益在工作窗边界快照；参数ramp按样本推进，宿主块大小不改变工作边界。此为新组件确定性集成行为，不声称参数自动化与原装逐bit一致。

加权调度先从区段几何与状态计算工作成本，再按固定hop的输入帧发放credit。Burg阶、AR阶、FIR初始化、IIR采样、区段和后处理分别计价；不依赖墙钟，不创建工作线程、不等待锁、不丢帧或工作。工作调度`deadlineMisses`表示在下一hop边界前仍有未完成算法工作，需要同步补齐的次数；它不等同于操作系统音频回调超时计数。最终测试均为0。高质量的纯CPU总量仍可超过实时预算，不能用调度计数0暗示实时一定达标。

`scheduled-equivalence.json`：48k四模式、44.1k标准、96k标准/高质量，共7组，按固定额外hop对齐同步安全版，所有可比Float32样本均零差。`final-original-comparison.json`把生产输出与最初原装AU输出对照：Type 1两品质在该输入下逐bit一致；Type 2长段按上述规则有意修复原厂UB，存在预期差异。

`core-safety.json` / `core-safety-repeat.json`：完整3秒Type 2标准在1/31/257/512/4096宿主块输出哈希相同；两个独立进程哈希相同；含增益ramp、De-Clip开关、旁路开关、NaN/Inf/超范围输入；未完成job中reset后重新播放亦相同。mono、高质量、16k/44.1k/96k/384k有限输出、旁路固定延迟逐样本一致、参数清洗及render零new均通过。`core-safety-asan.json` / `.log`为ASan+UBSan短程重复，全部通过且stderr空。

`stereo-isolation.json`：16k/48k/96k Type 2标准，静音右声道保持逐样本0，左声道与独立mono输出逐样本一致，避免原装高采样率越界读引入的跨声道污染。

修复子模块另有四模式共536声道窗、2,800,064个Double输出及151项系数缓存、Region状态全部逐bit一致的显式参考兼容验证，并完成该最复杂152声道窗的ASan+UBSan复核。详见 `Repair/RECOVERY.md`、`Repair/final-verification.json`、`Repair/weighted-cost-verification.json`。
